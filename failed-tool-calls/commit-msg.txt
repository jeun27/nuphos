fix(desktop): mark failed tool calls in the transcript

A finished call that threw, flagged isError or returned { error } now ends
in a red "Failed" or "Failed: <reason>"; a closed run of several calls
says "· N failed"; a call that returned an error stays out of the
Activity fold. The reason truncates before the label does.

The returned error is read from an object, from JSON text, and from MCP
text content, the shape Claude Code reports an MCP call's result in. The
reader threadBadges.ts used for this moves to toolResultRecord.ts and both
import it. A shell's text output stays its stdout: its failure is its exit
code.

Adds the e2e scenario "an upload of a file that is not there is marked
failed in the transcript", which reports the call to the app as Claude
Code does (E2E_SHOWN) and saves failed-upload-row.png.
